# Exact editorial content and Oriana cutover

GET `/api/editorial-control/:domain/:id` is a read-only extension of the existing shared editorial service. Domain is historia/publicacion only, ID is a canonical PostgreSQL integer, and no query parameters are accepted. Current active ID/role/session version are revalidated in the same repeatable-read read-only transaction used for the content/evidence read. All six current system roles can read; names/URL roles grant nothing. Inactive clients and archived pieces are404, as are missing records.

The closed response is `{version:1,piece,content}`. Piece uses the existing list projection/classification; content contains only the exact root columns idea, copy, material_referencia and aclaraciones, each string or null. No trim/truncation, raw metadata, salary/client-fee bags, auth attributes or whole rows are returned. Aggregate UTF-8 content above1MiB fails413 rather than silently truncating. The response bound is checked after the row read; it is not a claim that PostgreSQL avoids allocating/reading an oversized stored value. Evidence reuses annotateEditorialEvidence in that same transaction. The endpoint has no write route or new approval grant.

Principal Inicio adds a lazy native details disclosure per editorial row. It fetches only when opened, validates domain+ID and the **observed client ID**, and displays literal text with preserved line breaks and wrapping. Material is text, not an automatically opened link. Closing/unmounting aborts loading; identity/generation fences reject stale outcomes and errors hide prior data. No content is copied into localStorage. The existing publication-record control remains separate and authoritative for manual confirmation/withdrawal. No piece edit/approval action is invented by viewing content.

## Oriana-only retirement disposition

The old live dashboard's today/overdue/blocked/future-ready work is replaced by authoritative shared buckets and exact-piece content/status/evidence access. New Today/Overdue deliberately include broader pending/review work and exclude archived/inactive clients. The old daily published/total fraction is **not** recreated from a20-row page or asserted as actual publication. Its misleading waiting-for-approval subtraction and decorative checklist are not retained. Real publication confirmation, withdrawal and revision remain the existing guarded workflow, not a generic PATCH or optimistic state.

Assigned tasks, recorded material/feedback and transitions live in the principal task board with stable owner/collaborator IDs. `/oriana` aliases to the authenticated user's Inicio, or only one valid explicit task context. Name/role/client filters from the old URL are discarded, never interpreted as identity. The old Oriana source is preserved but its lazy import/live App branch are removed after bounded source/runtime checks. Líder/Germán remain live; their retirement is not authorized by this evidence.

This closes access to exact aclaraciones for both editorial domains, not the complete Render2.0 goal. Shareable exact-piece content routes, full piece editing/corrections, unknown historical data compatibility, broader browser/latency matrix and other master modules remain separate gates. Current NOT NULL scheduling and rejection-state limitations remain as documented in EDITORIAL_CONTROL_CONTRACT; no schema was relaxed to manufacture tests. Local implementation/verification is not production deployment or global release certification.
