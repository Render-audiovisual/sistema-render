## Identity and permissions

Current active supported human roles only, session_version revalidated inside transaction. All such users may read operational project metadata (shared agency workspace); no financial/account/private task bags. Admin creates projects, changes client/responsible/membership and archives/reactivates. Current responsible ID or admin may change ordinary project data, stages, milestones, deliverables and task links. Membership alone grants no structural write or review authority. No name-derived grants. Every mutation checks parent expected_revision, increments project revision once, writes explicit activity in the same transaction. Disabled/revoked/role changes deny. Archived project denies ordinary child/metadata writes; admin may explicitly reactivate via archivado:false. No hard-delete project API.
