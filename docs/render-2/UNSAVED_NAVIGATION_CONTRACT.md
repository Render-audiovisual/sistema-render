# Shared unsaved-navigation protection — local contract

Goal: preserve pending principal-task/delivery/correction, project, production and feedback drafts during ordinary same-document browser Back/Forward and section navigation. No commercial browser storage, backend/schema changes, automatic save or history-stack replacement/trapping. Existing App/Vite/preview dirt remains untouched. Prior integration was committed progress, not master completion. Superpowers guides bounded contract and independent verification.

## Shared API/ownership

New pure `frontend/src/shared/navigation/unsaved.js`: `registerNavigationGuard(win,getStatus)` returns idempotent unsubscribe. Status getter(context) returns `{dirty:boolean,busy:boolean}`; context `{from:string,to:string|null,type:'link'|'traverse'|'unload'}` uses same-origin relative path/query/hash. Registry in WeakMap per Window, no business values persisted. Errors/invalid getter results fail closed (busy). Read getter live at navigation, never capture stale draft snapshots. One consolidated confirm if any dirty; any busy denies without discard confirmation. Confirmation error denies. Generic message `Hay cambios sin guardar. ¿Querés descartarlos?`. Accepted navigation does not save/delete drafts itself; normal unmount clears page state. Clean navigation remains unchanged.

`installUnsavedNavigation(win)` idempotently installs: (1) existing cancellable render:before-navigation protocol listener; prevent canceled navigation, one prompt across guards; (2) beforeunload native warning if any dirty/busy, no custom confirm; (3) feature-detected Navigation API navigate listener ONLY same-document traverse when event.cancelable. On dirty refusal/busy call preventDefault BEFORE route/popstate commits; on acceptance do not intercept/rewrite/replay history or dispatch synthetic duplicate events. Never alter arbitrary history.state payloads, push/replace methods, entries, browser scroll restoration or routing. No monkeypatching native browser APIs. Return cleanup/idempotent installation handle for pure lifecycle tests. Main installs in main.jsx before React mount, not App effects (App/Vite dirt avoided).

New `frontend/src/shared/navigation/useNavigationGuard.js` React hook uses latest callback ref and effect register/unregister; StrictMode safe. Existing location.js validation/navigation event remains source protocol, not an authorization layer. For pages migrated below, remove their old before-navigation/beforeunload confirmation listeners to prevent duplicate prompts. Popstate listeners may restore location only, never undo a rejected browser event via replaceState or ask another confirmation. Existing local close/select confirmations remain exactly once where they already gate state changes before raw history writes; only migrate them to shared status/helper if needed, do not allow state updates after rejected navigation.

Platform boundaries are real, not hidden: current HTML navigate events can cancel many same-document traversals but browser may make traversal noncancelable (escape/rapid repeat, iframe, cross-document/origin). In noncancelable/unsupported cases do NOT implement a trapping go/replace loop. beforeunload still covers document exits where browser permits a warning. No promise of preventing forced exits, older same-document browsers without Navigation API, process termination or suppressed browser dialogs; these need real browser coverage and remain readiness limitations. Baseline feature-detection, unsupported/noncancelable events must not throw or freeze routing. Central protection is data-loss mitigation, never authentication/session blocking. Sources consulted: https://html.spec.whatwg.org/multipage/nav-history-apis.html#the-navigate-event and https://developer.mozilla.org/en-US/docs/Web/API/Navigation/navigate_event ; older Chrome overview incorrectly describes all traverse events as noncancelable, so use actual event.cancelable, not a browser/version guess.

## Proof and boundaries

Pure/controller: one confirmation, canceled URL/history unchanged, accepted traversal not reissued, busy denies, failed getter/confirm fail closed, supported/unsupported/noncancelable/cross-origin cases, unload, unregister/dispose/reinstall. Page source/model tests pin live dirty state and removal of destructive rollback/double-confirm paths. Actual built principal fresh guarded PostgreSQL/fictional accounts: edit project and cancel Back preserving URL/text, then accept Back; task/delivery/correction draft cancellation, unsent new task; production and feedback dirty exit; clean Back/Forward/reload retains ordinary routing. Desktop/mobile390px where feasible; confirm dialog interactions native only, no page evaluate mutations. Existing backend/frontend regression/build; no ordinary server start, external provider sign-in or production deployment. Completion of this bounded integration is not completion of every form in the master or proof on Safari/Firefox/older browsers.
